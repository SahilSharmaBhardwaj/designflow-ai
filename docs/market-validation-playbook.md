# DesignFlow AI — Market Validation & MVP Execution Playbook

Use this playbook before building any new product or feature to ensure the team solves a real market problem.

---

## 1) Pick a Real Market Problem

### Goal
Choose a painful, frequent, and expensive user problem instead of an idea-first solution.

### Exit Criteria
- Problem appears repeatedly across interviews/tickets/forums.
- Users describe active frustration and existing workaround behavior.
- The pain has clear business/user impact (time, money, risk, or churn).

---

## 2) Validate with Target Users

### Goal
Confirm the problem with direct user evidence.

### Minimum Evidence Standard
- 8–12 interviews in one target segment.
- Documented pain points, failed alternatives, urgency level.
- At least 3 users report trying workarounds or competitor tools.

### Interview Prompts
- “Walk me through the last time this problem happened.”
- “What did you try before? Why did it fail?”
- “What happens if this remains unsolved?”

## 4) Write Product Framing Before Build

### Required One-Page Brief
- **Problem Statement:**  
  “For [user segment], [problem] causes [impact], because [root cause].”
- **Target Audience:** Primary persona + context of use.
- **Success Criteria:** 3–5 measurable outcomes.

### Success Criteria Examples
- Time-to-complete decreases by X%.
- Task success rate increases to Y%.
- Weekly active usage reaches Z within N weeks.

---

## 5) Design a Focused MVP

### Goal
Solve one core pain point better than alternatives.

### MVP Scope Rules
- Include only must-have flows for core value delivery.
- Defer adjacent ideas to backlog.
- Define explicit non-goals.

---

## 6) Run Fast Real-User Tests

### Goal
Test usefulness, usability, and willingness to adopt/pay.

### Test Pack
- 5–7 participants from target segment.
- 3–5 scenario-based tasks.
- Post-task measures: completion, time-on-task, confidence/ease.
- Adoption signal: intent to use again / intent to pay.

---

## 7) Make a Relevance Decision

### Continue Only If Signals Are Strong
- Repeat usage or high intent-to-return.
- Clear value articulation from users.
- Positive trend on core metrics.

### Decision Matrix
- **Go:** Strong pull + acceptable usability.
- **Iterate:** Value is clear, usability gaps remain.
- **Pivot:** Weak pull, unclear value, or wrong segment/problem framing.

---

## 8) Build Professionally

After relevance is confirmed:
- Maintain product roadmap with milestone-based delivery.
- Keep architecture boundaries clear and scalable.
- Enforce coding standards and code review quality.
- Use version control discipline and CI/CD checks.
- Keep technical and product documentation current.

---

## 9) Ship in Small Iterations

### Cadence
- Ship small increments tied to measurable hypotheses.
- Track adoption, retention, and quality metrics per release.
- Use user evidence to prioritize next iteration.

### Core Metrics Set
- Activation rate
- Weekly retention
- Task completion rate
- Time-to-value
- User-reported satisfaction/ease

---

## 10) Pivot Early if Validation Is Weak

Pivot before overbuilding when:
- Users don’t return.
- Users can’t describe clear value.
- Better alternatives consistently win in evaluation.

### Pivot Options
- Problem pivot (same users, different pain point)
- Segment pivot (same solution shape, different users)
- Solution pivot (same problem, different product approach)

---

## Execution Checklist

- [ ] Real problem selected with clear evidence
- [ ] Target users interviewed and proof collected
- [ ] Market gap documented with competitor/alternative analysis
- [ ] Problem statement, audience, and success criteria finalized
- [ ] MVP scope constrained to one core pain point
- [ ] Fast user testing completed with quantitative + qualitative outcomes
- [ ] Go / Iterate / Pivot decision made with explicit rationale
- [ ] Professional build workflow established (roadmap, architecture, standards, CI/CD, docs)
- [ ] Iterative releases and metric tracking in place
- [ ] Pivot criteria monitored continuously
